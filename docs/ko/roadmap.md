# 로드맵 및 제약 사항

Jjan v1은 실제로 작동하고 검증을 완료한 MVP(최소 기능 제품) 단계입니다. "현재(Now)" 탭 이후의 내용들은 향후 구현할 로드맵이며, Jjan의 핵심 순환 에스크로 원형은 단순한 계모임 플랫폼을 넘어 다양한 응용 분야로 확장될 수 있습니다.

## 로드맵

{% tabs %}
{% tab title="현재 (Now)" %}
신뢰가 필요 없는 온체인 순환식 저축 곗방 기능이 **GIWA 테스트넷 상에 실시간 가동 및 코드 검증**이 완료되었습니다. 컨트랙트, 프론트엔드 연동, 배포가 모두 완료되었으며 지급 능력 인바리언트를 포함한 9개의 핵심 테스트 스위트가 완벽히 통과되었습니다.
{% endtab %}

{% tab title="가까운 목표 (Next)" %}
* **계정 추상화 및 묶음 트랜잭션 (Account Abstraction & Batched Transactions):** 사용자가 서명할 때 승인(Approve)과 참여(Join) 트랜잭션을 하나로 묶어 서명 1번으로 처리합니다.
* **세션 키 및 자동 납입 (Session Keys / Autopay):** 매 라운드가 돌아왔을 때 지갑 승인 팝업창을 띄우지 않고 백그라운드에서 사전에 위임된 자금을 자동으로 납입할 수 있도록 지원합니다.
* **마감 자동화 리레이어 (Relayer Automation):** 겔라토(Gelato)나 체인링크 킵퍼(Chainlink Keepers) 등 탈중앙화 킵퍼 오토메이션을 활용하여 라운드 타이머가 `0:00`이 되는 순간 자동으로 `closeRound()` 함수를 자동 호출하여 곗돈을 송금합니다.
* **소셜 로그인 온보딩:** Privy/Dynamic SDK 등을 통합하여 구글, 카카오 계정만으로 쉽게 지갑을 생성하고 로그인할 수 있도록 지원합니다.
* **타임락 기반 조기 비상 비활성화:** 곗방 멤버 중 일부가 이탈하여 곗방 전체가 정지 상태에 빠진 경우를 대비하여, 일정 기간이 경과하면 예치 보증금을 그대로 인출해 나갈 수 있는 `emergencyWithdraw()` 비상 환급 함수를 구현합니다.
* **디폴트 보증 풀 (Insurance Pool):** 일부 인원의 지속적인 미납으로 인한 리스크를 충당하기 위해 탈중앙화 예비 자금 풀을 도입합니다.
* **실제 KRW 스테이블코인 연동:** 모의 KRW(`MockKRW`) 대신 공식 브릿지 또는 법정화폐 연계 KRW 스테이블코인을 통화 수단으로 교체합니다.
{% endtab %}

{% tab title="미래 지향 (Then)" %}
* **가스비 대납 지원 (Gas Sponsorship):** 페이마스터(Paymaster)를 결합하여 GIWA 테스트넷 상의 트랜잭션 가스비를 플랫폼이 전액 대납하여 가스비 없는 쾌적한 UX를 실현합니다.
* **이자 획득형 에스크로 (Yield Escrow):** 매 라운드 사이에 에스크로 계좌에 묶여 있는 자금을 디파이(DeFi) 프로토콜에 예치하여 추가 이자 수익을 거둔 뒤 수령자에게 함께 배당합니다.
* **체인링크 VRF 무작위 순서 선정:** 온체인 난수(VRF)를 생성하여 곗돈 수령 순서를 편향 없이 무작위로 공정하게 배치합니다.
* **온체인 평판 신용 등급 활용:** [`ReputationRegistry`](technical/architecture.md)에 누적된 상환율과 신뢰 정보를 토대로 다른 디파이 프로토콜이나 대출 플랫폼에서 평판 점수를 신용 등급 지표로 연계 활용할 수 있게 합니다.
{% endtab %}

{% tab title="확장 (Scale)" %}
Jjan의 순환식 자금 에스크로 원형 기술은 단순한 계모임 외에도 **공동 구매(Group Buying)**, **커뮤니티 공제/보험(Community Insurance)**, 그리고 **소규모 동아리/DAO 공동 금고** 등 다방면으로 쉽게 확장되어 파생 상품을 빌드할 수 있습니다. Jjan은 이 핵심 원형을 실용화한 시작 제품일 뿐이며, 응용 가치는 무궁무진합니다.
{% endtab %}
{% endtabs %}

## 알려진 제약 사항 (테스트넷 MVP 단계의 의도적 설계)

아래 내용들은 MVP 설계 범위 안에서 신속한 검증을 위해 의도적으로 조정한 사항이며, 프로그램 오류가 아닙니다. 이 항목들은 Jjan의 핵심 안전 가치인 [비수탁 자금 보장](technical/security-model.md)에 어떠한 악영향도 주지 않습니다.

| 제약 사항 | 대응 및 구현 계획 |
| --- | --- |
| 실물 자산이 아닌 모의 토큰 `MockKRW` 사용 | 메인넷 가동 시 공인 브릿지된 실제 원화 스테이블코인으로 대체 |
| 무작위 난수 기반이 아닌 고정 수령 순서 | 로드맵 '미래 지향' 단계에서 체인링크 VRF 난수 배정 도입 |
| 정지된 곗방에 대한 비상 환급 수단 부재 | 로드맵 '가까운 목표' 단계에서 타임락 기반 `emergencyWithdraw()` 추가 |
| Web3 지갑 주입(Injected Wallet) 온보딩 | 소셜 로그인 SDK 통합 및 탑재로 지갑 생성 없이 시작 지원 |
| 보증금이 납입액 전액을 담보하지 않을 수 있음. 차감(Slashing) 한도가 `min(보증금, 납입액)`이므로, 곗돈을 수령한 뒤 납입을 중단한 멤버는 보증금을 몰취당하더라도 이후 라운드의 곗돈이 부족해질 수 있습니다. 컨트랙트의 지급 능력과 회계는 그대로 유지되지만, 나머지 멤버의 손실까지 메워주지는 못합니다. | 보증금을 납입액 이상으로 설정하거나 여러 라운드분을 함께 예치하도록 조정. 로드맵 '가까운 목표' 단계의 미납 보험 풀과, 곗방을 넘어 지갑에 따라다니는 신뢰도 점수(Reputation)로 이탈 비용을 높여 보완 |
