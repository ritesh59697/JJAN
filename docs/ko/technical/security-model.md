# 보안 모델

Jjan이 제공하는 가장 강력한 가치는 '누구도 곗돈을 탈취할 수 없다'는 점입니다. 이는 단순한 약속이나 선언이 아니며, 스마트 컨트랙트 코드 자체의 고유한 수학적/논리적 특성이며 엄격히 검증된 사실입니다.

## 비수탁형 자금 보증 (Non-custodial Guarantee)

{% hint style="success" %}
곗방(`Circle`) 컨트랙트에서 자금이 외부로 인출되는 경로는 오직 아래의 **두 가지**뿐입니다.

1. `closeRound()` 실행 → 해당 라운드에 **고정 약정된** 수령자에게 곗돈 총액 지급.
2. `withdrawBond()` 실행 → 보증금을 예치한 **해당 멤버 본인**에게 보증금 잔액 반환.

컨트랙트에는 오너(Owner), 관리자(Admin) 권한이 전혀 없으며, `selfdestruct`(자가 파괴)나 임의의 호출(Arbitrary Call)을 수행하는 코드 자체가 존재하지 않습니다. 즉, 곗방을 개설한 주최자라 하더라도 자금에 대해서는 일반 멤버와 동일하게 제어 권한을 가질 수 없습니다.
{% endhint %}

## 지급 준비성 일치 인바리언트 (Solvency Invariant)

가장 핵심이 되는 불변성(Invariant) 안전망 규칙은 다음과 같습니다:

```solidity
token.balanceOf(circle)  ≥  totalBonds + escrowedPot   // 즉, obligations()
```

쉽게 요약하면, **스마트 컨트랙트는 항상 자신이 지급해야 할 모든 부채(모든 멤버의 유효 보증금 총합 및 아직 수령되지 않은 납입금 총합)를 100% 충당할 수 있는 충분한 토큰을 보유하고 있어야 한다**는 의미입니다. 이 규칙이 깨진다면 일부 회원의 자금 가치가 보장받지 못한다는 뜻이 됩니다.

Jjan은 컨트랙트의 구조적 설계 단계부터 모든 자금 이동 시 장부상의 회계 변수(`totalBonds`, `escrowedPot`)를 엄격하게 연동 업데이트하도록 설계되었으며, 무작위 순서로 `join` / `contribute` / `closeRound` / `withdrawBond`를 무수히 반복 호출하는 Foundry **인바리언트 퍼즈 테스트(Invariant Fuzz Test)**를 통해 이 규칙의 안전성을 검증했습니다. 자세한 검증 방식은 [테스팅 및 검증](testing-and-verification.md)을 참조하세요.

## 보안 방어 대책

* **재진입 공격 방지 (Reentrancy Guard):** 자금이 이동하는 모든 함수는 `nonReentrant` 제어자를 포함하며, Checks-Effects-Interactions(검사-효과-상호작용) 패턴을 철저히 준수합니다. 실제 토큰 전송은 상태가 모두 업데이트된 후 가장 마지막에 수행됩니다.
* **보증금 출금 방식 (Pull Payments):** 보증금을 반환할 때 컨트랙트가 멤버들에게 자금을 밀어내는(Push) 방식이 아니라, 멤버가 직접 본인의 자금을 인출하는(Pull, `withdrawBond`) 방식을 채택했습니다. 이는 가스 고갈 공격이나 의도적 트랜잭션 거부로 인한 전체 시스템 마비(Griefing) 사고를 원천 방지합니다.
* **엄격한 권한 제어 (Access Control):** [`ReputationRegistry`](architecture.md) 평판 장부의 쓰기 권한은 오직 팩토리(Factory)로부터 배포 승인된 개별 `Circle` 주소에만 부여됩니다. 팩토리가 정상 등록한 곗방 외에는 그 누구도 평판 데이터를 위변조할 수 없습니다.
* **입력값 하드닝 (Input Hardening):** `initialize()` 초기화 함수는 `address(0)` 입력, 중복된 멤버 주소 목록, 그리고 참여 멤버 수가 2명 미만인 개설 시도를 원천 차단합니다. 또한, 이 함수는 단 1회만 호출 가능하도록 잠겨 있습니다.
* **결정론적 지급 실행:** 매 라운드의 수령자는 컨트랙트 개설 시점에 영구 고정되므로, 프론트런이나 채굴자 추출 가능 가치(MEV), 혹은 난수 조작에 의한 사기 행위의 여지가 전혀 없습니다.

## SafeERC20 사용

모든 토큰 관련 전송 및 허용량 확인 로직은 OpenZeppelin의 `SafeERC20` 라이브러리를 사용합니다. 표준 명세를 어기고 boolean 값을 반환하지 않거나 오작동하는 불량 ERC-20 토큰이 있더라도, 컨트랙트의 회계 장부가 무음 실패(Silent failure)하는 현상을 완벽히 방어합니다.

## 알려진 한계 및 제약 사항

현재 구현된 코드는 테스트넷 검증용 MVP 버전입니다. 일부 보안 강화책(예: 사고나 네트워크 장애 등으로 계원들이 전혀 반응하지 않고 정지된 곗방을 안전하게 초기화하고 보증금을 환급하기 위한 타임락 기반의 `emergencyWithdraw()` 함수 등)은 향후 메인넷 배포 단계 이전에 추가 탑재될 예정입니다. 자세한 로드맵은 [로드맵 및 제약 사항](../roadmap.md)을 참고해 주세요.
