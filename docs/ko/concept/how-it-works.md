# 짠 작동 방식

Jjan은 계모임 특유의 사회적 유대 및 친목적 요소를 그대로 유지하면서, 기존에 필수적이었던 개인 간의 '신뢰' 요소를 배제합니다. 블록체인 스마트 컨트랙트 자체가 계주 역할을 수행하므로, 실수를 하거나 거짓말을 하거나 돈을 갖고 도망가는 일이 원천적으로 불가능합니다.

## 진행 절차 (4단계)

{% stepper %}
{% step %}
### 개설 (Create)

개설자(계주)가 계원 주소(멤버), 라운드당 납입액, 예치 보증금(Bond) 및 수령 순서를 설정합니다. 트랜잭션 한 번으로 새로운 곗방(Circle)이 블록체인상에 생성됩니다.
{% endstep %}

{% step %}
### 참여 및 보증금 납입 (Join)

초대받은 멤버들은 공유 링크를 클릭하고 개인지갑을 연결하여 2번의 클릭(Approve & Join)만으로 보증금을 납입하고 즉시 참여합니다. 소셜 로그인 기능 덕분에 니모닉(복구 구문) 관리의 번거로움이 없으며, 기존 Web2 앱과 유사한 온보딩 경험을 제공합니다.
{% endstep %}

{% step %}
### 라운드 납입 (Contribute)

매 라운드마다 각 멤버는 약정된 고정 납입액을 컨트랙트 에스크로 주소로 입금합니다. 만약 라운드 제한시간 내에 납입을 하지 못할 경우, 예치했던 보증금의 일부가 삭감(Slash)되어 곗돈 풀에 자동으로 충당됩니다.
{% endstep %}

{% step %}
### 순환 지급 (Rotate)

해당 라운드의 납입 기간이 끝나면, 컨트랙트는 약정된 라운드 수령자에게 곗돈 전체를 자동으로 즉시 지급합니다. (GIWA 네트워크 기준 약 1초 내외 소요) 이후 시스템은 다음 라운드로 자동으로 진행됩니다.
{% endstep %}
{% endstepper %}

## 시스템이 신뢰를 보장하는 이유

* **자금이 특정 개인의 수중에 들어가지 않습니다.** 모든 납입금은 컨트랙트 에스크로에 보관되며, 오직 정해진 라운드의 수령 예정자에게만 지급될 수 있습니다.
* **수령 순서가 임의로 변경되지 않습니다.** 곗돈 수령 순서와 일정이 최초 개설 시점에 스마트 컨트랙트에 고정되므로, 중간에 임의로 지급 대상을 가로채거나 변경할 수 없습니다.
* **모든 모임원이 동일한 장부를 확인합니다.** 모든 납입, 지급, 보증금 삭감 등의 내역은 투명한 온체인 트랜잭션 이벤트로 기록됩니다.
* **약속 이행 데이터가 프로필이 됩니다.** 제때 납입했는지 연체했는지 여부는 지갑 주소에 종속되는 온체인 평판 점수(Reputation Score)로 관리되어 차후 다른 곗방에 가입할 때 참조됩니다.

## Web2처럼 쉽고 온체인처럼 확실하게

Jjan의 설계 목표는 처음 웹3를 접하는 사용자도 기존 핀테크 저축 앱(링크 공유, 간편 참여, 명확한 정산 주기)처럼 친숙하게 사용하도록 지원하면서, 그 바탕에 있는 보안성과 정산 보장은 신뢰할 수 있는 퍼블릭 스마트 컨트랙트의 무결성을 따르도록 구현하는 것입니다.

스마트 컨트랙트 코드가 이를 어떻게 강제하는지에 관한 상세한 사양은 [아키텍처](../technical/architecture.md) 및 [보안 모델](../technical/security-model.md) 페이지를 참조하세요.
