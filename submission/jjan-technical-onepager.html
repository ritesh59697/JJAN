Jjan rebuilds Korea's kye — informal rotating savings clubs — as a smart contract. Members contribute a fixed amount each round and the pot rotates to one member at a time, but the contract custodies every won and pays the scheduled recipient automatically. There is no admin key and no code path that can divert the pot, so the organizer-rug that plagues traditional kye becomes impossible. Built on GIWA because many small, recurring payments only feel good on a fast, near-free chain.

System architecture

CircleFactory
Deploys each circle as an EIP-1167 clone of one implementation; authorizes it to write reputation.
→
Circle
Per-club escrow & rotation state machine. Holds the stablecoin; enforces every rule below.
→
ReputationRegistry
Global per-wallet reliability score; only factory-authorized circles may write deltas.

Contributions and bonds are held in MockKRW, a testnet KRW stablecoin (open faucet) that a real bridged/canonical stablecoin replaces on mainnet. One Circle implementation is deployed once; every new club is a minimal-proxy clone, so creating a circle costs a fraction of a full deployment.

Circle lifecycle

join()
Invited member posts a bond; joins the circle.
start()
Opens round 1 once every member has joined.
contribute()
Pays the fixed amount into escrow this round.
closeRound()
Slashes no-shows, pays the fixed recipient, rotates.
withdrawBond()
Returns remaining bond after the circle finishes.

Payout order is fixed at creation, so each round's recipient is deterministic and never caller-selectable. A member who misses a round is slashed up to one contribution from their bond into that round's pot, keeping the circle solvent and honest members whole. closeRound() is callable by anyone once the round window elapses.

Security model

  • No custodial drain. Funds leave a circle only via closeRound (to the round's fixed recipient) or withdrawBond (to the member). No owner, admin, selfdestruct, or arbitrary-call path exists.
  • Solvency invariant. balance ≥ liveBonds + unpaidEscrow holds by construction and is proven under fuzzing (see verification).
  • Reentrancy. Every fund-moving function is nonReentrant and follows checks-effects-interactions; bonds use pull-payment.
  • Access control. Only factory-authorized circles write reputation; the factory alone can authorize.
  • Input hardening. Duplicate and zero-address members and a <2-member circle are rejected at init; the clone initializer is one-shot.

Testing & on-chain verification

  • 9 / 9 tests green — unit, a 256-run fuzz test for pot conservation, and a handler-driven solvency invariant.
  • Invariant: 128,000 randomized calls, zero reverts — balance ≥ obligations() never broke across random join/contribute/close/withdraw sequences.
  • Deployed & source-verified on GIWA Sepolia (chain 91342) via Blockscout; deploy cost ≈ $0 at ~0.001 gwei.

Tech stack

Contracts: Solidity 0.8.24, Foundry (fuzz + invariant), OpenZeppelin (ReentrancyGuard, SafeERC20, Clones, ERC20).
Frontend: Next.js 15 (App Router), wagmi v2 + viem, TanStack Query. Injected connector for the MVP — connector-agnostic, so social login (Privy/Dynamic/Web3Auth) is a one-file swap.
Deploy: Foundry scripts to GIWA Sepolia; Blockscout verification.

Why GIWA

A club is many small, recurring transfers — unusable on L1. GIWA's OP-Stack L2 gives ~1s blocks and ~200ms Flashblocks preconfirmations, so a payout lands the instant a round closes, and near-zero gas makes micro-contributions viable. Upbit distribution adds a Korea-native user base and a direct funding path into circles.

Roadmap & known limitations

Next: social-login onboarding · timelocked emergencyWithdraw() for stalled circles · missed-round insurance pool · a real KRW stablecoin. Then: yield on idle escrow · VRF payout ordering · credit scoring from reputation. Scale: the same escrow-and-rotate primitive → group buying, community insurance, club treasuries.

Current limitations (by design, testnet MVP): uses MockKRW not a real stablecoin; payout order is fixed rather than VRF-randomized; a stalled circle has no early-exit yet (planned emergencyWithdraw); onboarding is via an injected wallet, not yet social login. None affect the custody guarantee.
